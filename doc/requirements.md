# Trello風タスク管理アプリ 要件定義書 v0.2

## 1. 背景・目的

本プロジェクトは、アプリ開発学習を目的として、Trello風の簡易タスク管理アプリを作成するものである。

クライアントは自分自身であり、実業務での本格運用ではなく、アプリ開発の基本的な流れを理解することを主目的とする。

ただし、単なる練習用の画面作成ではなく、小規模Webアプリ開発を想定し、以下を段階的に学べる題材とする。

- 要件整理
- 画面設計
- データ設計
- DB保存
- タスクの追加・編集・削除
- タスクの進捗管理
- 期限切れ表示
- 実装と検収の流れ
- GitHubへのcommit / push

## 2. ゴール

本MVPのゴールは、以下を実現することである。

- 1つの固定ボード上でタスクを管理できる
- Todo / Doing / Done の3カラムで進捗管理できる
- タスクを追加できる
- タスクを編集できる
- タスクを削除できる
- タスクを別のカラムへ移動できる
- タスクに期限と優先度を設定できる
- 期限切れタスクを画面上で把握できる
- タスクデータをDBに保存できる
- ページを更新してもDBからタスクを再取得して表示できる
- 実装内容をGitHubへcommit / pushできる

## 3. 対象ユーザー

本MVPの対象ユーザーは、個人ユーザー1名とする。

MVPでは以下は対象外とする。

- 複数ユーザー利用
- チーム共有
- ログイン
- 権限管理

## 4. スコープ

### 4.1 MVPで対応する範囲

| 分類 | 対応内容 |
|---|---|
| ボード | 1つの固定ボードを表示する |
| カラム | Todo / Doing / Done の3カラムを表示する |
| タスク追加 | 任意のカラムにタスクを追加できる |
| タスク編集 | タイトル、期限、優先度を編集できる |
| タスク削除 | 確認後にタスクを削除できる |
| タスク移動 | ボタン操作で隣接カラムへ移動できる |
| 期限管理 | 期限を日付で設定できる |
| 優先度管理 | 4段階の優先度を設定できる |
| 期限切れ表示 | 未完了かつ期限超過のタスクに表示する |
| データ保存 | DBに保存する |
| 初期データ | サンプルタスクを用意する |
| Git管理 | 実装内容をcommit / pushする |

### 4.2 MVPで対応しない範囲

| 対象外 | 理由 |
|---|---|
| ログイン機能 | MVPでは個人利用に限定するため |
| 複数ユーザー | 認証・権限設計が必要になるため |
| 複数ボード | まずは1ボード固定で進めるため |
| カラム追加・削除・名称変更 | 将来拡張とするため |
| ドラッグ＆ドロップ | 初期実装の難易度を抑えるため |
| フィルタ・並べ替え | 将来拡張とするため |
| コメント | MVP範囲外 |
| 添付ファイル | MVP範囲外 |
| 通知 | MVP範囲外 |
| スマホ最適化 | MVPではPC利用を優先するため |
| テストコード | MVP完成後の学習項目とするため |

## 5. 機能要件

### 5.1 タスク追加

ユーザーは各カラムからタスクを追加できる。

入力項目は以下。

| 項目 | 必須 | 内容 |
|---|---:|---|
| タイトル | 必須 | タスク名 |
| 期限 | 任意 | 日付 |
| 優先度 | 必須 | 低 / 通常 / 高 / 緊急 |

仕様:

- 押したカラムにタスクを追加する
- 新しいタスクはカラムの一番下に追加する
- タイトル未入力の場合は保存できない
- 優先度未選択の場合は保存できない
- 期限は未入力でも保存できる
- 保存後、フォームを閉じてカードを表示する
- キャンセル時は入力内容を破棄してフォームを閉じる

### 5.2 タスク編集

ユーザーは既存タスクの以下項目を編集できる。

- タイトル
- 期限
- 優先度

仕様:

- タイトル未入力の場合は保存できない
- 優先度未選択の場合は保存できない
- 期限は空にできる
- 保存後、カード表示に戻る
- キャンセル時は変更を破棄してカード表示に戻る

### 5.3 タスク削除

ユーザーはタスクを削除できる。

削除時には確認ダイアログを表示する。

```text
このタスクを削除しますか？
```

仕様:

- OKの場合、タスクを削除する
- キャンセルの場合、削除しない

### 5.4 タスク移動

ユーザーはボタン操作でタスクのカラムを移動できる。

| 現在 | 移動先 |
|---|---|
| Todo | Doing |
| Doing | Todo / Done |
| Done | Doing |

MVPでは以下の直接移動は行わない。

- Todo → Done
- Done → Todo

### 5.5 期限切れ表示

以下の条件を満たすタスクに `期限切れ` と表示する。

```text
期限が今日より前
かつ
カラムがDoneではない
```

Doneカラムのタスクには、期限が過去でも `期限切れ` と表示しない。

### 5.6 データ保存

タスクデータはDBに保存する。

ページ更新後も、DBから再取得してタスクを表示する。

## 6. 入力チェック・メッセージ

| ケース | メッセージ |
|---|---|
| タイトル未入力 | タイトルを入力してください |
| 優先度未選択 | 優先度を選択してください |
| DB取得失敗 | データの取得に失敗しました |
| DB保存失敗 | 保存に失敗しました |
| DB更新失敗 | 更新に失敗しました |
| DB削除失敗 | 削除に失敗しました |

タイトルは前後の空白を除去して保存する。
空白のみの場合は未入力扱いとする。

期限は任意。
過去日も入力可能とする。

## 7. 非機能要件

| 項目 | 内容 |
|---|---|
| 対応端末 | PC |
| 対応ブラウザ | Google Chrome 最新版 |
| スマートフォン対応 | MVPでは対象外 |
| データ保存 | DBに保存する |
| 認証 | MVPでは実装しない |
| セキュリティ | 認証なしのため、本番運用や機密情報保存は想定しない |
| パフォーマンス | 個人利用を前提とし、タスク100件程度までを想定 |
| 可用性 | 学習用MVPのため、商用レベルの稼働保証は行わない |
| アクセシビリティ | 重要情報は色だけでなくテキストでも表示する |

## 8. 前提・制約事項

- 本MVPは学習目的で作成する
- 本格的な業務利用は前提としない
- 認証機能は実装しない
- 複数ユーザー利用は対象外
- 初期状態では1ボード固定とする
- カラムは Todo / Doing / Done 固定とする
- DBは学習目的で利用する
- DBテーブルは `tasks` の1テーブルのみとする
- Supabase URL や anon key などの環境変数は `.env.local` で管理する
- `.env.local` はGitHubにpushしない
- `.env.example` を作成する

## 9. 検収条件

MVP完了条件は以下とする。

| No | 確認内容 |
|---:|---|
| 1 | タスクボード画面が表示される |
| 2 | Todo / Doing / Done の3カラムが表示される |
| 3 | 各カラムからタスクを追加できる |
| 4 | タイトル未入力ではタスク追加できない |
| 5 | 優先度未選択ではタスク追加できない |
| 6 | タスクのタイトル・期限・優先度を編集できる |
| 7 | タスクを削除できる |
| 8 | 削除時に確認ダイアログが表示される |
| 9 | タスクを隣接カラムへ移動できる |
| 10 | 期限切れタスクに `期限切れ` と表示される |
| 11 | Doneカラムのタスクには期限切れ表示されない |
| 12 | DBに保存されたタスクがページ更新後も表示される |
| 13 | 初期データが正しく表示される |
| 14 | `.env.local` がGit管理対象外になっている |
| 15 | `.env.example` が作成されている |
| 16 | 実装内容がGitHubへpushされている |
